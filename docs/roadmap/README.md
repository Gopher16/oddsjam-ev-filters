## Programme phases

A (R01–R04) establishes operating documentation and traceability; B (R05–R07)
strengthens evidence/context contracts; C (R08–R10) covers manual refresh; D
(R11–R15) covers task-oriented UI/charts; E (R16–R19) builds guided discovery;
F (R20–R22) connects tracking/evaluation; G (R23–R29) develops correlated exposure
and the integrated risk laboratory; H (R30–R33) joins diagnosis, explanation and
Section 5 acceptance. Conditional phases I–N (R34–R60) explore independent capture,
models/strategies, execution, fantasy, expansion and sustainable operations.
The register's actual dependency clauses control entry, not this broad sequence.

R01–R03 are merged. R04 implementation is locally verified; remote checks and merge remain pending. Future features are
not implemented merely because their row exists. The next normal candidate after
R04's verified merge is R05, subject to its own source review and plan. No dates,
external spending, framework rewrite or trading activation are promised here.

The existing [multidimensional implementation ledger](../plans/MULTIDIMENSIONAL_IMPLEMENTATION_STATUS.md)
remains the detailed current-capability reference; the original discovery brief
remains historical context. For today's use start with the [documentation home](../README.md),
[operating workflow](../operations/ODDSJAM_WORKFLOW.md) and
[evidence gaps](../operations/EVIDENCE_GAPS.md). A study's evidence readiness and
external application remain distinct from software merge status.
