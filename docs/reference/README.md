## Separate approved policies

- [Exploratory research and models](policies/EXPLORATORY.md): historical arm
  comparisons and bounded explanatory models, alongside the separate core policy.
- [Prospective promotion and bounded pilots](policies/PROMOTION.md): predeclared
  future family, one terminal look, human review and non-resetting deployment caps.

This consolidation changes neither policy, defaults, formulas nor source publications.
A policy's support gate is not another stage's default, a power guarantee or a
production authorization. Exact configurations and their validators remain linked.

## Where explanations moved

Existing component URLs remain useful entry points. Canonical ticket/opportunity,
economics and timing sections now link here; continuous-EV units/quality and scanner
setting states point to EV/settings; prioritization contrasts and model feature
interpretation point to their shared references. Approved policy sections link to

original guides rather than being copied into a second operational specification.

## Missingness and strength of claim

Unknown evidence remains null/unavailable with a reason, never an invented zero,
false, unset control or platform default. A measured zero and a supported false
assertion are valid values. A failed gate is a known failure; an unassessed gate is
not automatically false. Read each field's status and denominator: some audit counts
are legitimately zero even when a return is undefined.

Historical association → model explanation → prospective result → production
review are distinct claims, not an automatic escalation. No chart, model utility,
positive return, elapsed date or name authorizes an external change. Even approval
requires separate confirmed application before monitoring an applied version.
